Exact Cartesian optimization TODO
================================

Planned work only. Prioritize native double relate/set operations with stored
approximation output. Preserve exact decisions, borrowed original supports,
operation-scoped ownership and the agreed strict floating-point contract.

Filtered predicate optimizations, in priority order:

   1. Use monotonic rounding for scalar comparisons (coordinates and measures).
      Given approximations a, b with certified absolute errors ea, eb, compute
      d = RN(a-b) and s = RN(ea+eb) in the same round-to-nearest format.
      If |d| > s, return sign(d). Proof: if |a-b| <= ea+eb, monotonicity
      gives RN(|a-b|) <= RN(ea+eb), and symmetry gives RN(|a-b|) = |d|.
      Thus strict separation proves |a-b| > ea+eb and the true operands
      have the indicated order, even if the error sum rounded down. No
      inflation is needed. A tie is inconclusive; retain the direct
      comparison for two zero errors and the fallback for uncertain cases.

   2. Avoid filtering a signed measure twice. In RootSignedMeasure::sign(),
      use the stored determinant sign when its certified bound excludes zero;
      respect negation. Otherwise use exact orientation. Where only a sign
      is wanted, call orientation directly instead of constructing a measure.

   3. Defer adaptive side tests during segment rejection. Keep the immediate
      rejection when the first pair of signs certifies strict separation.
      If a sign is inconclusive, try the reverse pair's cheap filters before
      refining: strict separation there makes the missing sign irrelevant.
      Retain certified signs and resolve only those the caller still needs.

   4. Certify exact native subtractions from the input box. On each axis,
      Sterbenz's lemma applies if all coordinates lie in [m, 2m] or its
      negative reflection for some m > 0. If both axes qualify, orientation
      compares two rounded products of exact differences. Distinct products
      certify their order by monotonicity; on a tie compare exact product
      residuals using FMA under the exponent-range contract, or fall back.
      Do not apply this certificate to uncertain constructed coordinates.

   5. Reduce orientation on a known common support. If a and b lie on the
      original directed line s->t, side(a,b,p) is side(s,t,p) when a
      precedes b along s->t, its negation in reverse order, and zero if a=b.
      This holds even for p off the support. Use certified support and order
      already available at the call site; avoid a general support search.

   Side and dot: write the exact expression as P + s*Q, with s = -1 for
   side and +1 for dot. P and Q are products of coordinate differences.
   - Reuse certified factor signs from coordinate order or a prepared segment.
     If P and s*Q have the same nonzero sign, return it without multiplying.
     Drop a certified zero term; opposite signs can cancel. For uncertain
     coordinates, item 1 above can certify a difference sign. Profile reuse
     separately from computing four signs just for this shortcut.
   - If all four differences are exact for the true points (e.g. item 4),
     compare p = RN(P) directly with -s*q, q = RN(Q). Strict order proves
     the sign by monotonicity; equality needs residuals or fallback. An
     N-ULP guarantee alone does not certify exact differences.
   - Given approximate products p,q with existing absolute error bounds Ep,Eq,
     accept sign(d) for d = RN(p + s*q) if |d| > RN(Ep + Eq), by item 1.
     This removes only the final rounding allowance. Do not build separate
     product certificates solely for this test if a combined bound is cheaper.
   - For eager points with |true - approx| <= eta*|approx| per coordinate,
     form M by replacing each difference in P,Q by the sum of its absolute
     input coordinates and adding the two resulting products. Accept when
     |d| > RN(C*Mhat), where Mhat is M evaluated in binary64. With u=2^-53,
     round C upward from (2*eta + eta^2 + ((1+u)^3-1))/(1-u)^3.
     This covers input errors, rounded differences/products and rounding M;
     monotonicity handles the final +/- in d. Compare with the precomputed
     box threshold below on the same certified layout.
   - Baselines: side_robust on native doubles for side; the existing dot
     filter for dot; stored-error filters for uncertain points. Count eligible
     calls as well as successful exits, especially rounded-product ties and
     opposite-sign cancellation. As arithmetic references (adds including
     subtracts / multiplies / abs), native side_robust's magnitude path is
     6/3/3, three-point N-ULP magnitude is 10/5/7, and a prepared box
     threshold is 5/2/1 excluding setup. Compare measured cost and fallback
     rates, not just operation counts.

   Division-free certificate for native binary64, RN to nearest/even, no
   overflow/underflow. For Z = a + (T/D)*U, let t = RN(n/d), h = RN(U),
   y = a + t*h (mathematical only), z = fma(t,h,a) = RN(y), u = 2^-53.
   Require |T-n| <= 8u*MT, |D-d| <= 8u*MD and a certified 0 < L <= |D|.
   Choose a positive compile-time constant rounded DOWN from
     c_N <= N*(1-2u)^(N+1)*(1-u)^4/(1+u).
   Once per intersection compute:
     v = fma(|t|,MD,MT);  w = fma(8,v,|n|);
     H = fma(|t|,L,w);    B = RN(c_N*L).
   Per axis accept z if RN(|h|*H) < RN(|z|*B). Strict order survives
   unrounding the products. Since |T-t*D| <= u*(|n| + 8*(MT + |t|*MD)),
   the three nonnegative FMAs give |Z-y| <= u*|h|*H/(L*(1-u)^4).
   Bound |Z-y|, not |Z-z|: the final rounding is common to both results.
   For RN(Z) to differ from z by N+1 or more steps, the path from y to Z
   must span N entire intervening rounding cells. Each is at least
   u*(1-2u)^(N+1)*|z| wide in the normal range, even across a binade
   boundary. Acceptance puts |Z-y| strictly below their combined width.
   At N=1 one full cell still intervenes (c_1 = 1-16u suffices); at N=0
   none does. Correct rounding needs an exactness or rounding-boundary test.

   Extra cost: 3 FMAs + 1 multiply shared, then 2 multiplies + 1 comparison

   FMA determinant retries (costs per determinant unless stated otherwise):
   - Keep the current head k = RN(p-q), p = RN(a*b), q = RN(c*d).
     If a,b,c,d are exact endpoint differences, recover the exact product
     tails ep = fma(a,b,-p), eq = fma(c,d,-q). If p-q is also exact
     (e.g. by Sterbenz), ep == eq certifies k exactly: 2 FMAs + 1 compare.
     Otherwise, with s = RN(ep-eq), use 2*|s| if p-q is known exact, or
     2*fma(u,|k|,|s|) if not. The latter costs 3 FMAs + 1 subtraction
     + 1 scaling. Tightening this bound changes neither k nor the candidate.
   - Alternative initial head (Kahan): q = RN(c*d), e = fma(-c,d,q),
     f = fma(a,b,-q), k_new = RN(f+e). For exact endpoint differences,
     the relative error is <= 2u, so 4u*|k_new| is a certified bound even
     after product cancellation. Both determinants and bounds together:
     2 multiplies + 4 FMAs + 2 adds + 2 scalings, excluding differences.
     Do not attach this bound to the old head. If replacing heads on retry,
     recompute the quotient, its residual and the associated candidates.
   - Rounded differences: Kahan certifies a*b-c*d for the stored factors,
     not the determinant of the original edges. Given M = RN(|p|+|q|),

     the endpoint subtraction tails A=a+da, B=b+db, C=c+dc, D=d+dd.
     TwoDiffTail costs 5 adds/subtracts per existing head, at most 30 for

Enrichment and traversal (implementation order)
----------------------------------------------
Scope: exact Cartesian straight-segment overlay on valid polygonal inputs.

1. Reuse exact position order and record the successor copy decision together.
   Keep a temporary ordinal for each distinct (x,y) from the exact cluster
   sort, including singletons and any discarded blockers seen by enrichment.
   Do not use cluster_id: cleanup can reset it. Lexicographic position is
   strictly monotone along a nonzero straight segment, including verticals.
   Order same-segment turns by ordinal in the directed segment's order;
   keep the existing operation tie rules only at equal ordinals.
   When enrich_assign selects the successor operation, record whether to
   copy intervening ring vertices. Traversal then needs neither a scan of
   both target operations nor a second segment_position predicate. Preserve
   full round trips; equal position alone does not imply wraparound.
   The read-only next_turn/next_operation helpers can also return references.

2. Remove two proven redundancies in exact cluster processing.
   - In the ray comparator, side(T,R,L) = -side(T,L,R). Evaluate only one
     orientation and preserve the incoming/outgoing tie rule at zero.
   - In handle_spikes, equal-ranked rays lie on the same line through T.
     For an unshifted connection its opposite endpoint is on that support,
     so side(current.opposite_point,current.point,next.point) cannot be
     positive. Skip this repair on the exact path and omit opposite_point
     where only the repair needs it. Keep general spike and closure handling.

3. Make areal cluster zone counting linear after angular sorting.
   Reverse-scan cyclic connections to find the same next outgoing connection
   per source as the existing search. Add each covered half-open rank interval
   to a difference array and prefix-sum once. Preserve equal-rank connection
   order, split wrapping intervals, and count equal start/end ranks as empty.
   This is a counting optimization, not a consequence of numerical exactness.

4. Proof required before reusing ray ranks in edge selection.
   At ambiguous clusters, retain incoming and outgoing ranks. Prove that
   the stored incoming rank describes the actual arrival direction even
   after collinear output simplification. Only then select among distinct
   eligible rays by cyclic rank, after operation and component filtering.
   Equal rays still require path/ownership selection: even a shared target
   node need not mean the same ring path. Cover equal rays and distinct round
   trips separately. Do not infer that component search, visited-path checks
   or reversed-operation compensation can be removed.
